1. WHAT YOU ARE DESIGNING IN THIS SESSION
========================================
The full main app for RECOVERY COMPANION — a personal recovery operating system ("This app remembers my recovery so I don't have to"). Supportive-companion tone, low cognitive load, one primary action per screen.

BOTTOM TAB BAR (5 tabs): Home · Timeline · Check-in (center, visually prominent, largest target) · Progress · Profile

 1. HOME: morning encouragement card ("You're on Day 46. Compared to last week: ✅ Pain down ✅ Walking improved. Recovery isn't always linear. Keep going."), big friendly Day-N counter, today's actions (check-in / medication / exercise), next appointment card, latest insight card, "Generate doctor report" entry point.
 2. TIMELINE: vertical chronological recovery history mixing check-ins, notes, medications, photos, appointments, milestones (milestones visually celebrated, e.g. "Walked without crutches 🎉"); filter chips; floating add-entry button (note/photo/milestone/medication/appointment).
 3. DAILY CHECK-IN: ONE screen, under 30 seconds, one-handed, tap-only — mood (😊 😐 😣), pain 0–10 slider, energy/sleep/mobility 3-level taps, medication yes/no toggle, one optional single-line note, one big Done → celebratory confirmation (soft checkmark/confetti < 1s, light haptic). Missing days never shamed — returning users get a gentle "welcome back".
 4. PROGRESS: pain trend chart with milestone markers, weekly comparison card, sleep/energy/mobility trends, plain-language insight cards ("Pain tends to increase after poor sleep") — color-code data types with the pastel category hues from the design system.
 5. PROFILE: account, manage recoveries, medications, appointments, education hub, reports history, premium status row, settings, medical disclaimer.

DETAIL SCREENS:
 6. DOCTOR REPORT PREVIEW (flagship): consultation summary a clinician scans in 60 seconds — header (condition, Day N, range), "What changed since last visit" block, graphs, key timeline events, medications, photo strip; print/PDF-friendly restrained styling; date-range selector.

2. COLOR & DESIGN SYSTEM — BEARABLE-INSPIRED (same as session 1)
========================================
- Original palette in Bearable's spirit (never their exact hex): deep indigo/plum-tinted dark surfaces (~#15141F-family, never pure black; elevated surfaces slightly lighter, warm-tinted) with lavender/violet primary accent, plus muted pastel category hues color-coding pain / sleep / energy / mood / medication across chips, charts, and timeline entries. Light variant: soft off-white ~#F8F7FC base, white cards, desaturated accents. Deliver BOTH modes for every screen.
- 60-30-10 neutral/secondary/accent. Red/coral/amber reserved for safety states only.
- Accessibility: WCAG AA (4.5:1 body, 3:1 UI), ≥44pt targets, thumb-zone placement for daily actions, never meaning by color alone, charts need text-summary alternatives, survive large text.
- Typography: one humanist sans, max 3 weights, large expressive numerals (Day counter, pain score).
- Layout: cards, 8pt grid, 12–16 radius, soft low shadows. Skeleton loaders, optimistic UI.
- Motion: micro 100–150ms, components 200–300ms, screens 300–350ms, ease-out entrances, gentle springs for celebrations; charts draw in 400–600ms staggered on first view only; nothing flashing/looping.

========================================
3. PREMIUM PLACEMENT — BEARABLE-STYLE (core of this session)
========================================
Model the premium experience on how Bearable does it: the free tier is genuinely usable daily; premium is surfaced contextually where its value is felt, never as a hard wall.
- FREE forever: daily check-in, timeline, journal, basic pain chart, medications, appointments, safety content.
- PREMIUM: advanced insights & correlations, full/unlimited history depth (free shows e.g. last 30 days), doctor report export, photo compare, multiple simultaneous recoveries, education deep-dives.
- Design the contextual touchpoints:
  a) Locked insight/correlation cards on Progress: real card layout, slightly desaturated + the consistent lock badge from session 1, with a one-line value hook ("See how sleep affects your pain") — tapping opens the paywall sheet.
  b) History-depth gate on charts: a soft gradient fade at the free-history boundary with an inline "Unlock full history" pill.
  c) Doctor Report: preview fully visible, EXPORT button carries the lock badge (value first, gate at output).
  d) A small non-intrusive premium row in Profile with current plan status.
  e) PAYWALL as a bottom sheet (not full-screen takeover) reachable from all gates: benefit checklist using pastel category hues, 14-day trial + monthly, price transparency, restore purchases, easy dismiss. Never dark-patterned; dismissing always leaves the free experience intact.
- Locked treatment must be identical everywhere (badge size, desaturation level, tap behavior) — spec it once in the system sheet.

========================================
4. MANDATORY ANNOTATION RULE (most important)
========================================
For EVERY screen and component, ALWAYS write descriptive specification notes alongside the design (and as structured comments in any generated code). Output goes to an AI coding agent implementing 1:1 in React Native + react-native-reanimated. Document per screen:
- TRANSITIONS: entry/exit type, exact ms, easing (e.g., "check-in opens as modal slide-up, 320ms, ease-out; paywall bottom sheet spring, damping 0.85").
- BUTTONS/INTERACTIVE ELEMENTS: default/pressed/disabled/loading states, visual changes, press timing + haptics, and what each tap triggers/navigates to (including every locked element → paywall sheet).
- EFFECTS: shadows (color/opacity/blur/offset), gradients (stops + hex, incl. the history-fade gate), blurs, overlays, haptics — exact values.
- ANIMATION CHOREOGRAPHY: entry order, stagger delays, durations, easings (e.g., "Home cards fade+rise 16px, 250ms, 60ms stagger"; "Done → checkmark draw-on 600ms + light haptic"; "milestone overlay spring-in ≤1s").
- COMPONENT SPECS: sizes, paddings, radii, font sizes/weights/line-heights, exact hex per element.
- STATES: empty (with one obvious next action), loading (skeletons), and error for every data screen; plus locked state where relevant.
